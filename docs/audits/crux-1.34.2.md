# CRUX Audit — forjar 1.34.2

## Method

**When, and from what.** Written on 2026-11-17 on `release/v1.34.2`, cut from
origin/main `7a8eda78`, against the `[1.34.2]` section of `CHANGELOG.md`. Gate H
(`scripts/dogfood/crux-reconcile.sh`) reads 11 behaviour paragraphs in that
section; each has one row below. The one-line "also merged" bullets (runner pool
planning functions with no caller, typed errors, refactor, tests only, CI only,
repository only) ship no forjar behaviour and have no row. The round-1 review of
this PR found that the first draft had promoted one paragraph and left about ten
behaviour changes as one-liners; they are promoted here.

**Who wrote it.** A Claude model (Sonnet 5.5, a release-prep worker). No quorum
has reviewed this file.

**What was measured, and what was not.**

- The forjar half of every row is carried from the CHANGELOG paragraph, the
  merged diff of the PR named, and the tests that PR added. Each row cites the
  test name with `file:line` at origin/main `7a8eda78`; those names and lines
  were read from that tree for this file. No forjar binary or workflow was run
  for this file, and a cited test passing is CI's record on main, not a
  measurement made here.
- Every comparator is `not_measured`. The comparator text is from each project's
  public documentation as the author knows it; no comparator was installed or
  run, and no version is claimed.

This file records that a comparison was written for each behaviour. It is not
evidence that forjar matches or beats any system named here, and gate H cannot
tell a real comparison from three names typed into a cell.

| PR Gate no longer runs on pull_request_target (PMAT-913, PR #935) | SLSA, Sigstore, in-toto | forjar (carried): `pr-gate.yml` triggers on `pull_request` and runs only for a same-repository head; a new job `no-pull-request-target` fails a PR whose workflow files use the `pull_request_target` trigger. Evidence: `tests/falsification_no_pull_request_target.rs`. Comparators (`not_measured`): SLSA's build requirements separate the build from untrusted inputs and ask that a build's parameters not be controllable by the submitter beyond those declared; Sigstore and in-toto record who built what from which source, and neither runs a submitter's code with the repository's privileges. The finding: the change moves the PR gate to the same separation, with the trigger no longer granting a fork's code the base repository's token. Difference that stays: a PR from a fork no longer gets the gate at all (same-repository heads only), so fork contributions are not gated by this job. |

Comparators (`not_measured`): Terraform's `aws_instance`, Crossplane's AWS instance resource and Pulumi's `aws.ec2.Instance` take the same placement, image and storage inputs as declared fields. Difference that stays: none of the three, as the author knows them, refuses to launch until a parity-gate file, a spend cap and a kill switch are all present; that gate is forjar's own and is untested against any real provider here. |
| cloud_instance apply launches with a deterministic client token, adopts, prints the id; its generated script exits 75 on capacity (PMAT-861; PR #1146; issues #1134-#1137) | Terraform, Crossplane, Kubernetes | forjar (carried): `run-instances` gets a client token from the launch parameters and the UTC day; a box found by that token is adopted; the id's state is read before `launched <id>`; a dead box spends the token and the next token is tried, at most 32 calls; the generated apply script exits 75 on an AWS capacity code. Evidence: `src/resources/cloud_instance/tests_launch.rs:160` (`client_token_is_derived_stable_and_valid`), `:188` (`run_instances_carries_the_client_token`), `:198` (`apply_last_line_is_launched_id`), `:216` (`error_then_token_lookup_adopts_the_box`), `:278` (`capacity_codes_exit_75_other_errors_keep_their_code`); `tests_chain.rs:46` (`a_dead_box_spends_the_token_and_the_next_token_relaunches`), `:81` (`a_chain_of_dead_boxes_stops_at_the_bound`), `:104` (`a_failed_state_read_is_retried_three_times_then_refused_naming_the_id`). Comparators (`not_measured`): Terraform records the instance id in its state and re-reads it, and an instance made outside it is adopted by `import`, not by a token; Crossplane records an external name on the managed resource; Kubernetes controllers reconcile to a declared object and retry. Difference that stays: forjar keeps no state for the box and finds it again by a token that depends on the day, so a declaration unchanged across a UTC day boundary derives a new token and relies on the owner lookup to find the box. Whether `forjar apply` codegen reaches this path on a real account was not measured. |
| cloud_instance destroy fails closed and checks spot request ids before terminate (PMAT-861, PR #1102; issues #1095, #1096, #1098) | Terraform, Pulumi, Crossplane | forjar (carried): a failed spot-request or post-terminate lookup is an error, never "destroyed"; only `None` or `sir-` plus 8 lowercase alphanumerics is accepted, checked before any terminate call. Evidence: `src/resources/cloud_instance/tests_b4.rs:279` (`only_whole_spot_request_ids_are_cancelled`), `:299` (`a_malformed_spot_request_id_stops_destroy_before_any_terminate`), `:323` (`a_failed_spot_request_lookup_is_an_error_before_any_terminate`), `:338` (`a_failed_post_terminate_lookup_is_an_error_never_destroyed`). The finding: each keeps "could not ask" apart from "gone"; forjar now does for this resource. Difference that stays: forjar finds owned instances by a tag lookup, not a state file, so a tagging change is invisible to destroy. |
| cloud_instance refuses a bad or unresolved templated value before any provider command (PRs #1036, #1063, #1120, #1126; issue #1044) | Terraform, Ansible, Pulumi | forjar (carried): a template that resolves to a bad value, or is still unresolved at code generation, produces no provider command; a templated field does not hide a bad literal sibling at parse time. Evidence: `src/resources/cloud_instance/tests_resolve.rs:61` (`a_template_resolving_to_a_bad_value_produces_no_provider_command`), `:101` (`an_unresolved_template_reaching_codegen_is_refused`), `:84` (`a_good_resolved_value_still_launches`); `src/core/parser/tests_cloud_instance_validate.rs:109` (`templated_vs_literal_fields_table`); `src/resources/cloud_instance/tests_b1.rs:417` (`a_templated_type_or_price_is_not_rejected_at_parse_time`). Comparators (`not_measured`): Terraform validates variable types and `validation` blocks before a plan reaches a provider; Ansible renders templates at task time and an undefined variable fails the task by default; Pulumi checks inputs before create. The finding: all three refuse a value known bad before the provider call, which forjar now does for this resource at both parse and render. |
| github_release check verifies a declared checksum and asserts the pinned version before running the binary (PRs #1068, #1066; issue #1049) | Ansible, Nix, Bazel | forjar (carried): a declared `checksum:` is compared with the installed file before the binary runs; a malformed value diverges and never reaches the script; a pinned version must equal the live binary's reported version. Evidence: `src/resources/tests_github_release_checksum.rs:51` (`matching_checksum_converges_with_or_without_prefix_and_case`), `:66` (`wrong_checksum_diverges_and_the_binary_is_not_run`), `:74` (`malformed_checksum_diverges_and_never_reaches_the_script`); `src/resources/tests_github_release_verified.rs:37` (`pinned_version_must_equal_the_live_version`), `:59` (`failed_run_or_stderr_only_version_is_unknown`). Comparators (`not_measured`): Ansible's `get_url` accepts a `checksum` and verifies the download; Nix fixed-output derivations fix the content hash of the fetched file; Bazel's `http_archive` takes a `sha256` and fails the fetch when the downloaded archive does not match. Difference that stays: both verify at fetch time; forjar's check verifies the file already on the host, so it detects later replacement, but only if the pin is declared. |
| github_release apply refuses a pin older than the live binary, reading the version as check does (PR #1073; issue #1067) | Terraform, Ansible, Nix | forjar (carried): `apply` reads the live version with the check reader and refuses to install a pin older than the binary on the box; unversioned pins are not ordered against it. Evidence: `src/resources/tests_github_release_downgrade.rs:67` (`fj613_apply_refuses_a_pin_older_than_the_live_binary`), `:152` (`fj1067_apply_guard_reads_a_stderr_only_version_and_a_failed_run`). Comparators (`not_measured`): Terraform's `required_version` and provider version constraints refuse a tool older than the constraint; Ansible's package module with `state: present` does not downgrade, while `state: latest` upgrades; Nix pins by hash, so a downgrade is a different store path rather than a refusal. The finding: forjar adds an explicit no-downgrade guard that the comparators get from their constraint or state model. |
| A copy op cannot SIGPIPE (PR #1144; issues #1122, #1124, #1125) | Ansible, Salt, Puppet | forjar (carried): the delta-patch copy step is `head -c N \| tail -c +M` instead of `tail -c +M \| head -c N`, so no writer closes early and the script does not exit 141 under `pipefail`. Evidence: `src/copia/tests.rs:222` (`patch_script_copy_never_sigpipes_on_a_large_basis`). Comparators (`not_measured`): Ansible's `copy`, Salt's `file.managed` and Puppet's `file` do not stage their copy through a shell pipeline; each hands the transfer to its own runtime or to `rsync`/`cp`. The finding: the bug exists because forjar generates shell, which those tools mostly avoid for this step. Whether the fix is exercised end to end over ssh was not measured. |
| An unpinned cargo package is cached under its resolved upstream version (PR #1058; issue #1048) | Nix, Bazel, Ansible | forjar (carried): the cache key uses the newest published version resolved by `cargo search`; if it cannot be resolved the install builds without the cache; a pinned version keeps its key and script. Evidence: `src/resources/tests_package_e.rs:70` (`fj1048_unpinned_key_tracks_resolved_version`), `:85` (`fj1048_unresolved_builds_without_cache`), `:113` (`fj1048_hostile_resolved_version_bypasses_cache`), `:55` (`fj1048_pinned_key_unchanged`). Comparators (`not_measured`): Nix keys every build by the hash of its inputs and Bazel keys actions by declared inputs, so a moving `latest` is not a key in either; Ansible's `cargo` module with `state: latest` asks cargo each run. Difference that stays: forjar's key is still a version string from the registry, not a content hash, so a re-published same-version crate is not seen. |
| The default inode_pressure watch skips /proc and /sys pseudo-filesystem masks (PR #1094; issue #847) | Kubernetes, Docker, systemd | forjar (carried): with no `mounts:` listed, `/` and every tmpfs are judged except tmpfs mounts under `/proc` and `/sys`, matched on a path boundary; a mount listed explicitly is always judged. Evidence: `src/core/inode_pressure/tests.rs:202` (`default_watch_skips_proc_and_sys_masks`), `:215` (`explicit_mount_under_proc_is_still_judged`), `:229` (`proc_and_sys_prefix_matches_on_a_path_boundary_only`). Comparators (`not_measured`): the Kubernetes kubelet's eviction signals for `nodefs.inodesFree` and `imagefs.inodesFree` watch the node and image filesystems, not the runtime's masked pseudo mounts; the node-level inode alerts commonly shipped with Prometheus exporters exclude pseudo filesystem types by an fstype filter; Docker masks `/proc` paths with a read-only tmpfs, which is the case measured in CI. The finding: skipping pseudo mounts is the usual rule; forjar's is by path, not by filesystem type. |
| The pre-push hook blocks only on cargo fmt; the other checks warn (PR #1108; issue #859) | Kubernetes, Bazel, Nix | forjar (carried): `cargo check`, clippy, `cargo test --lib` and the quorum gate still run and print `WARN`; only a formatting failure blocks the push. Evidence: `scripts/hooks/pre-push-test.sh:38` (`fmt-blocks` rc=1), `:39` (`check-warns` rc=0), `:40` (`clippy-warns` rc=0), `:42` (`quorum-warns` rc=0).
