# CRUX Audit — forjar 1.34.1

## Method

**When, and from what.** First drafted on 2026-11-12 for the two paragraphs then
under `[1.34.1]` (rows 1 and 15). Completed on 2026-11-13 on `release/1.34.1`,
cut from origin/main `a5087bbe`, against the `[1.34.1]` section of
`CHANGELOG.md` after `[Unreleased]` was folded into it. Gate H
(`scripts/dogfood/crux-reconcile.sh`) reads 15 behaviour paragraphs in that
section; each has one row below. The one-line "also merged" bullets are not
behaviour paragraphs for the gate and have no row. Two paragraphs that were in
`[Unreleased]` (the weekly Stress Tests lane, PMAT-673, and the SEC005 test pin,
#649) change CI and tests only, ship no forjar behaviour, and were moved into
that one-line list as `CI only:` and `Tests only:`, as the v1.34.1 list already
did for #972 and #978.

**Who wrote it.** A Claude model (Opus 5.5, a forjar-cop worker). No quorum has
reviewed this file.

**What was measured, and what was not.**

- Row 1, forjar half: measured when #993 merged. The falsifier
  `tests/falsification_992_timeout_needs_no_kill_binary.rs` fails with the old
  code and passes with the fix (`.quorum/fix-992-timeout-kill-by-syscall.json`).
- Rows 2 to 14, forjar half: carried from the CHANGELOG paragraph and the tests
  the merged PR added. No forjar binary was built or run for this file.
- Row 14 reuses the v1.34.0 measurement of the same comparators
  (`docs/audits/crux-1.34.0.md`, row 1); those measurements were not re-run.
- Row 15, forjar half: carried from the review of #930, not re-run.
- Every other comparator is `not_measured`. The comparator text is from each
  project's public documentation as the author knows it; no comparator was
  installed or run, and no version is claimed.

This file records that a comparison was written for each behaviour. It is not
evidence that forjar matches or beats any system named here, and gate H cannot
tell a real comparison from three names typed into a cell.

## Reconciliation

| Behaviour | Systems | What the comparison found |
|---|---|---|
| --resource-timeout bounds the apply on a host with no kill binary (PMAT-992, #992) | systemd, Docker, Podman, Kubernetes | forjar (measured): the timeout path signals the script's process group with the `killpg` syscall, so a 2 s timeout ends a 30 s script on an image without procps; before the fix it spawned an external `kill` and ignored the error. Comparators (`not_measured`): systemd stops a unit past `RuntimeMaxSec=`/`TimeoutStopSec=` by signalling the unit's cgroup from the manager; `docker stop --time` and `podman stop --time` send SIGTERM then SIGKILL through the runtime; Kubernetes ends a pod past `activeDeadlineSeconds` or its grace period through the kubelet. None needs a `kill` program inside the workload's image. Difference that stays: they signal a cgroup or a container, so a process that leaves its group is still caught; forjar signals a process group, so a child that calls `setsid` escapes (#1002, not fixed in 1.34.1). |
| apply --check resolves {{secrets.*}} through the manifest's secrets: provider (PMAT-1011, #1011) | Ansible, Terraform, OpenTofu, SOPS | forjar (carried): `check` now passes the manifest's `secrets:` block as `apply` does, so a `sops`, `op` or `file` secret no longer fails `not found` under `--check` only. Comparators (`not_measured`): Ansible's `--check` evaluates variables, vault values and lookups the same way a real run does; Terraform and OpenTofu `plan` evaluate variables, providers and data sources with the same configuration `apply` uses; SOPS decrypts the same way whatever the caller intends to do with the value. The finding: each comparator resolves inputs identically in its dry run and its real run, which is the rule this fix restores. `forjar test` still has the old call (stated in the CHANGELOG). |
| A file resource stages to a per-run name, not a fixed one (PMAT-638, #638) | Ansible, Chef, Puppet, Salt | forjar (carried): the atomic replace now stages at `<path>.forjar-new.$$` instead of a fixed `<path>.forjar-new`. Comparators (`not_measured`): Ansible's `atomic_move`, Chef's file resource with `atomic_update`, Puppet's file type and Salt's `file.managed` each write a temporary file in or next to the destination and rename it into place; the documented temporary names come from the language's temp-file facility (random, created exclusively), not from a PID. Difference that stays: a PID name is guessable and is not created with `O_EXCL`; the CHANGELOG states this and accepts it. |
| build.rs resolves contracts/ when it runs, not when it was compiled (PMAT-194, #456) | Bazel, Nix, Guix | forjar (carried): the build script reads `CARGO_MANIFEST_DIR` at run time and re-runs when it changes, so a reused build-script binary no longer reads another checkout's `contracts/`. Comparators (`not_measured`): Bazel keys every action by its declared inputs, so a step whose input path changed is not reused; Nix and Guix build in a sandbox from content-addressed inputs, so a build cannot read a path it did not declare. The finding: the comparators make this class of stale read impossible by construction; forjar's fix closes the one known path through Cargo's `rerun-if-env-changed` and does not make the build hermetic. |
| forjar build layers the base image its config declares, and fails when it is absent (PMAT-989, #989, IMG-001) | Docker, Podman, Nix, Bazel | forjar (carried): the build loads the base OCI layout from `state/images/`, puts its layers first, copies their blobs and keys the cache on the base; an absent or broken base is an error naming the `skopeo copy` that supplies it. Comparators (`not_measured`): `docker build` and Podman/Buildah resolve `FROM` and pull an absent base from a registry; Nix `dockerTools.buildImage` takes `fromImage` as a fixed-output input with a hash; Bazel `rules_oci` takes the base as a pulled, digest-pinned repository. Difference: forjar never pulls; the base must already be on disk, which keeps the build offline and makes a missing base an error rather than a network fetch. |
| forjar build executes packages and command into a layer on the declared base (PMAT-989, #989, IMG-001 3/N) | Docker, Podman, Nix, Bazel | forjar (carried): `packages` and `command` run in a container from the base and the filesystem changes become one extra layer (sorted, epoch mtime, volatile paths normalised, whiteouts). Comparators (`not_measured`): Docker and Podman/Buildah make one layer per `RUN` and keep the build-time mtimes unless `SOURCE_DATE_EPOCH` handling is asked for; Nix `dockerTools` runs `runAsRoot` in a VM and normalises timestamps; Bazel `rules_oci` runs nothing inside the image and builds layers from tar files only. Differences: forjar produces one layer for all steps; package versions are unpinned (stated), so two builds can differ where Nix's cannot. The falsifiers need Docker and are not run by CI (stated). |
| Changed: command: on type: image is now a build step, not the entrypoint | Docker, Podman, Kubernetes, Nix | forjar (carried): `command:` on an image resource is now run at build time; the new `entrypoint:` field sets what the image runs. Comparators (`not_measured`): a Dockerfile or Containerfile (Docker, Podman) separates `RUN` (build) from `ENTRYPOINT`/`CMD` (runtime); Kubernetes' `command` overrides the image's entrypoint at runtime; Nix `dockerTools` sets `config.Entrypoint` apart from build steps. The finding: forjar now has the same build/run split all four keep. A config that used `command:` as the entrypoint changes meaning on upgrade; the CHANGELOG marks it as a change and the release notes name it. |
| ResourceType prints in its serde spelling in the CLI; the cron check guard skips only on a sudo refusal (PMAT-916, #433, #848, #445) | Terraform, Ansible, Puppet, Chef | forjar (carried): CLI output prints the type as the config spells it (`wasm_bundle`), not the Rust Debug name; the cron check probes the crontab read and treats a sudo refusal as SKIP and an absent crontab as `missing:`; apply refuses a damaged marker block by name. Comparators (`not_measured`): Terraform prints resource types as written in configuration; Ansible's cron module marks its entries with `#Ansible: <name>` comments, Puppet's with `# Puppet Name: <name>` and Chef's with `# Chef Name: <name>`, and each rewrites the entry under its marker. Difference: forjar refuses to touch a crontab whose marker block is damaged, where the documented comparators do not describe that case. |
| Encryption is now a default feature (PMAT-893, #893) | SOPS, Vault, Ansible | forjar (carried): `cargo install forjar` now includes age, so `secrets keygen/encrypt/decrypt` work without a feature flag; `keygen -o` creates the file 0600 and refuses to overwrite. Comparators (`not_measured`): SOPS ships age and PGP support in its default build; Vault's encryption is not optional; `ansible-vault` ships with ansible-core. The finding: all three ship their secret encryption on by default, which forjar now does. |
| BREAKING: forjar secrets encrypt no longer takes the secret as an argument; the secrets family never echoes one (PMAT-893, #895) | Vault, Ansible, Kubernetes, SOPS | forjar (carried): the positional value is removed; plaintext comes from stdin or `--from-file`, and errors in the `secrets` family never print the value or a path. Comparators (`not_measured`): `vault kv put` accepts values on argv and offers `-` for stdin and `@file`; `ansible-vault encrypt_string` accepts argv and offers `--stdin-name`; `kubectl create secret generic --from-literal` takes argv and offers `--from-file`; SOPS encrypts files, not argv values. The finding: the three that take a value on argv all keep argv; forjar refuses it outright, which is stricter and breaks scripts that passed it (stated). Residual risk stays: core dumps are not disabled and buffers are not zeroed (stated). |
| check and apply --check count an unreachable host as unmeasured, exit 4 (PMAT-659, #659) | Ansible, Salt, Terraform | forjar (carried): a host that never answered is reported `UNMEASURED` with exit 4 instead of `fail`. Comparators (`not_measured`): Ansible reports an unreachable host as `UNREACHABLE` apart from `failed` in its recap and `ansible-playbook` exits 4 when a host was unreachable; Salt reports a minion that did not return separately from a failed state; Terraform `plan` errors when a provider cannot reach its API rather than reporting drift. The finding: the comparators keep "could not ask" apart from "asked and it differs", which forjar now does. |
| lock-prune -f is scoped to the config it is given (PMAT-661, #661) | Terraform, OpenTofu, Pulumi | forjar (carried): prune touches only the machines the config declares and refuses a machine another stack's stamp also lists. Comparators (`not_measured`): Terraform and OpenTofu keep one state per backend and workspace, and `state rm` removes only addressed resources; Pulumi keeps state per stack and `pulumi state delete` takes one URN. The finding: no comparator has a prune that walks every state in a directory; forjar's shared state dir is what made the bug possible, and the fix scopes it to one config. |
| drift with an empty state dir compares the declared pin live (PMAT-912, #852, #613, #694) | OpenTofu, Docker, SOPS, Terraform | forjar (carried): with no lock for any machine, `drift` treats the run as lockless and compares a declared pin with the live binary, offline too, instead of inspecting 0 resources and exiting 0. This closes the gap the v1.34.0 audit measured (`crux-1.34.0.md` row 1: `drift --offline` on a state dir with no lock printed `No drift detected. 0 resource(s) inspected`). Comparators (from that audit, not re-run): OpenTofu and Terraform `required_version` pin the tool itself, not a binary they install; Docker lets a tag move with no comparison; SOPS compares its own binary with the upstream latest and no pin. The finding stands: no surveyed system compares a live host binary with a declared pin. |
| The disk-budget reaper deletes only what it can prove dead (GH-667, GH-669, GH-936; #667, #669, #936) | Nix, Guix, Docker, Bazel | forjar (carried): every candidate gets an in-use check (`/proc/*/cwd`, `fd`, `exe` and mapped files) before `rm`; an unreachable target deletes nothing and exits 1; an empty or timed-out `/proc` scan proves nothing. Comparators (`not_measured`): the Nix and Guix garbage collectors treat paths found through `/proc` (open files, maps, executables) as runtime roots and keep them; `docker system prune` keeps images and volumes a container uses and deletes the rest by filter; Bazel's disk-cache collection deletes by age and size. The finding: forjar's rule is the Nix/Guix one (prove unused before delete), and it now refuses to fall back to an age sweep, which Bazel's collector is. |
| State locks carry an owner id, are per machine, and can wait (FJ-LOCK-001 C3-C5, #923 #924 #925; merged as #930) | Terraform, OpenTofu, Pulumi | forjar (carried from #930, not re-run): the lock records a uuid, host, boot id, pid and start time; release removes only a lock this process owns; `--force-unlock <ID>` refuses a live local holder; `--lock-timeout` waits in FIFO order; locks are per machine plus a short global lock. Comparators (`not_measured`): Terraform and OpenTofu write a lock with an ID, the operation, the holder and the time; `-lock-timeout` retries until the time is up; `force-unlock <LOCK_ID>` does not test whether the holder is alive; the lock covers one state, not one host. Pulumi locks a stack for an update and has `pulumi cancel`. Differences: forjar's unlock refuses a live local holder where the documented command does not; the holder check is local only, so a live holder on another host is not detected by pid. |
