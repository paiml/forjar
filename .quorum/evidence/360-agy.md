# agy /teamwork lane — #360 / #362 (sandboxed plan-mode review of the preview on the integrated tree, scrubbed HOME)

## VERDICT
The `fix/drift-observables` branch successfully avoids a lock schema change but introduces two critical flaws: it double-reports drift for file resources due to an incomplete refactor, and it silently orphans cron jobs if their command marker is missing. The implementation relies on string manipulation hacks rather than structured state, placing it below industry defaults.

## REFUTED CLAIMS
*   **The mask breaks if a field name is a prefix of another (`mode` vs `mode_bits`):** Refuted; `is_masked` uses exact string equality (`f == key`) on the split token (`src/core/observation_mask.rs:204`).
*   **The mask breaks if a value contains `=`:** Refuted; `split_once('=')` isolates the first key correctly and preserves the value (`src/core/observation_mask.rs:203`).
*   **The mask breaks for a generator whose output is not `key=value` (content hash, MISSING):** Refuted; `split_once('=')` returns `None` for these tokens, causing `is_masked` to return `false` and leave them untouched (`src/core/observation_mask.rs:205`).
*   **`content` in `ignore_drift` bypasses the hard error:** Refuted; `content` is excluded from the file vocabulary, so `unhonoured_ignore_drift` flags it as an error during validation (`src/core/observation_mask.rs:169`).
*   **The mask is applied at one writer but not another:** Refuted; all three writers (`record_success`, `refreshed_live_hash`, `check_nonfile_drift`) use `observation_mask::masked_for`.
*   **ObservationMaskChanged censuses unmasked baselines as drift:** Refuted; `check_nonfile_drift` explicitly detects differing mask keys and calls `census.skipped(..., SkipReason::ObservationMaskChanged)` instead of reporting drift (`src/tripwire/drift/mod.rs:323`).
*   **The next apply fails to re-baseline under the current mask:** Refuted; `record_success` records the current mask in `details` and hashes the digest under it (`src/core/executor/resource_ops.rs:81`).
*   **Cron exact-line `-x` check is flawed:** Refuted; `grep -qFx` correctly searches for the exact, literal string, preventing substring matches (`src/resources/cron.rs:79`).
*   **Cron block deletion breaks on names with awk-special characters or backslashes:** Refuted; the markers are passed literally via shell environment variables and compared exactly with `awk`'s `==` operator (`src/resources/cron.rs:520`).
*   **Cron block deletion breaks on an empty crontab:** Refuted; it prepends a harmless blank line when piping empty strings via `echo "$EXISTING"`, but does not crash or corrupt state.
*   **The falsifiers pass vacuously:** Refuted; `FakeCrontab::apply` genuinely executes the bash script and writes to the fake store, and the mask tests explicitly assert `drift_count >= 1` after tampering.
*   **Pre-existing tests were edited to fit false expectations:** Refuted; changes in `tests_cron_b.rs` merely updated string assertions to match the new `awk` variables.

## CONFIRMED CLAIMS
*   **Cron block deletion fails on a crontab with the marker but a hand-edited entry:** Confirmed; the `awk` script drops `# forjar:name` (`d=1;next`) but because the next line lacks `# forjar-cmd:name`, the condition `d==1&&$0==ENVIRON["FJ_C"]` fails. It resets `d=0` and prints the hand-edited entry, effectively orphaning it while applying the new block at the bottom (`src/resources/cron.rs:520`).

## UNIQUE FINDINGS
*   **Duplicate Findings for File Resources:** By removing the `rl.resource_type == ResourceType::File` exclusion from `detect_nonfile_drift`, file resources are now evaluated *twice* during `detect_drift_full_reported`. `detect_drift_with_lifecycle` appends a finding for content hash mismatches, and `detect_nonfile_drift` immediately appends a second finding for the live hash mismatch on the exact same resource. This creates duplicated reports (`src/tripwire/drift/mod.rs:250`).

## CRUX SURVEY
*   **Ansible:** The `cron` module parses crontabs using Python into dictionaries, targeting jobs based on `#Ansible: <name>` comments and replacing the job cleanly via AST-like parsing.
*   **Puppet:** The `cron` resource type delegates to a dedicated provider that natively parses and rewrites crontab blocks identified by `# Puppet Name: <name>` rather than relying on brittle shell text processing. To ignore drift, Puppet uses the `audit` metaparameter, which requires structured state tracking per attribute.
*   **Terraform:** Employs a structured JSON state mapping and uses the `lifecycle.ignore_changes` block to skip drift detection on explicit attributes during the plan phase.
*   **Verdict:** This design is **below the industry default**. Masking string stdout prior to hashing and modifying crontabs via regex/awk filters is fragile compared to the AST/structured map approaches used by Ansible, Puppet, and Terraform.

## Disposition

- Twelve attacks refuted by the lane itself with file:line evidence (mask prefix/`=`/non-key output/content, every writer masked, ObservationMaskChanged census, re-baseline, cron exact-line, awk-special names, empty crontab, vacuity, edited expectations).
- Confirmed: a hand-edited entry under a forjar marker stays and a fresh block is appended. Deliberate (delete only what forjar wrote) and pre-existing; the honest follow-up — refuse by name — filed as #445.
- Unique finding: file resources double-reported because the `ResourceType::File` exclusion was dropped — COUNTERED: the diff does not touch that line (`src/tripwire/drift/mod.rs:75` at the merge-base); the lane read main's comment about an earlier change as this branch's.
- CRUX verdict "below the default" — accepted for the crontab parser (structured replacement, #445); not accepted for the ignore semantics, which match Terraform/Puppet in effect on a transcript substrate.
