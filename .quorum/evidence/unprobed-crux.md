# Quorum evidence — PMAT-221 — CRUX

The question: what does a world-class system print when it could not measure the thing a plan depends on?

- **Bazel / Nix** — the input hash IS the action key. Bazel hashes every declared input before it decides whether an action is up to date, and a remote executor receives the digests, never a guess; a Nix derivation's store path is a function of its inputs. "Unmeasured" is unrepresentable by construction: there is no path on which an action is reported up to date without its inputs having been hashed. forjar's probe is the same idea applied to a task's declared inputs — and until this ticket it had a silent path around it for every machine the controller does not answer for.
- **Ansible `--check`** — a host the controller cannot reach is reported UNREACHABLE in the recap, in its own column beside ok/changed/failed, and the play's exit status reflects it. A host that was not measured is never counted as ok. That is the census shape forjar's `drift` already had and its planner now has: a separate, named count, not a fold into "unchanged".
- **Terraform `plan -refresh=false`** — the counter-example. Skipping the refresh is an explicit flag, and the plan then compares config to state alone; the output carries no per-resource marker that a resource's real state was not read. Operators learn this from the documentation, not from the plan. forjar's default before this ticket was that shape without the flag: lock-relative for remote build I/O, and silent about it.

Verdict: accept the Bazel/Nix stance that the action never proceeds on an unhashed input where the hash can be taken, and the Ansible stance that a host not measured gets its own named column; reject the Terraform stance that an unmeasured resource may print as clean. forjar cannot hash a remote tree from the controller without a round trip (that is what `--refresh` is for), so the honest fix is the Ansible column: name the rows, keep the action, say which instrument can answer.
