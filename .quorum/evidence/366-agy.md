# agy /teamwork lane — #366 / #369 (sandboxed plan-mode review, scrubbed HOME)

# VERDICT
The pull request correctly identifies the root causes of both the silent policy scope mismatch (comparing `serde` strings against `Debug` spellings) and the arithmetic anomaly in `policy-coverage` (collapsing rules that share a message into one identity). However, the implementation is severely incomplete. The `Debug` spelling bug remains in dozens of locations across the CLI surface, and the newly introduced `display_id_at(index)` creates a brittle, order-dependent identity that introduces TOCTOU (Time-of-Check to Time-of-Use) vulnerabilities for MCP clients and fails to account for explicit ID collisions.

# REFUTED CLAIMS
* The implicit claim that the `Debug` spelling defect for `ResourceType` is fully resolved is false; there are approximately 50 remaining unaddressed instances of `format!("{:?}", resource_type)` across the CLI (e.g., `src/cli/fleet_reporting.rs:261`, `src/cli/check_test.rs:333`, `src/cli/privilege_analysis.rs:94`).
* The claim that `display_id_at(index)` serves as a stable, cross-run identity is false; it causes the identity to shift if policies are reordered, meaning `remediate` and `policy-coverage` can completely disagree across runs (`src/core/types/policy_rule_types.rs:580`).

# CONFIRMED CLAIMS
* `total_rules == rules_triggered + untriggered_rules.len()` is now a structural property because `trigger_split` partitions by array index, guaranteeing every rule lands in exactly one bucket (`src/core/policy_coverage/mod.rs:259`).
* Policies scoped to multi-word resource types silently failed open on main because `matches_scope` compared the user-provided `serde` spelling against the lowercased `Debug` spelling, rendering the rule inert (`src/core/parser/policy.rs:177`).
* The old `display_id()` calculation collapsed un-id'd rules with the same message into a single key, incorrectly dropping satisfied rules from the coverage report (`src/core/types/policy_rule_types.rs:183`).

# UNIQUE FINDINGS
* **Explicit ID Collisions:** A user explicitly naming a rule `id: RULE-1-slug` perfectly collides with the generated fallback identity for a different rule at index 1 that shares the same slug.
* **Duplicate Explicit IDs:** The validation logic still does not reject duplicate explicit IDs (e.g. `id: SEC-1` defined twice). This allows `remediate` to overwrite failure reasons for twin rules because it keys its `ReasonMap` on that non-unique ID.
* **MCP Caller TOCTOU:** By injecting the array index into the ID (`RULE-<index>-<slug>`), the shipped MCP tool (`forjar_remediate`) becomes highly unstable for automated agents. If an LLM reads a coverage report and then inserts a new rule at the top of the file before remediating, the target index shifts and the tool silently edits the wrong policy.
* **Falsifiers Are Non-Vacuous:** The added falsification tests dynamically parse and assert on the computed lengths and values rather than hardcoding tautologies, ensuring they do not pass vacuously.

# CRUX SURVEY
This design operates **below the industry default**.
* **Kyverno:** Rules are defined inside a `ClusterPolicy` list. Every rule **must** have an explicit, user-defined `name:` field. Missing or duplicate names are strictly rejected by the Kubernetes API.
* **HashiCorp Sentinel:** Rules are explicitly named variables (e.g., `main = rule { ... }`). A missing identifier or a duplicate rule name in the same file is an immediate syntax error.
* **OPA / Gatekeeper:** Policies are Rego rules or `ConstraintTemplate` CRDs, identified by their package/rule name or `metadata.name`. The Kubernetes API or Rego compiler structurally enforces uniqueness.
* **ansible-lint:** Rules have explicitly defined, unique alphanumeric IDs (e.g., `yaml[octal]`). Custom rules must declare one to allow skipping or overriding. 

By falling back to an array index combined with a message slug, Forjar introduces cross-run instability and collision hazards that industry-standard policy engines avoid by enforcing explicit, unique identifiers at the parsing stage.


## Disposition

Two refutations, both accepted as scope corrections rather than code changes on this branch:

- "The Debug-spelling defect is fully resolved" — the branch never fixed the ~50 display-only sites; the claim text was narrowed to the surfaces #366 names and the remainder is filed as #433.
- "`display_id_at(index)` is a stable cross-run identity" — it is order-dependent; the TOCTOU on `forjar_remediate`, the explicit/generated collision and the undiagnosed duplicate explicit ids are one problem with one industry answer (mandatory explicit unique ids), filed as #434. The branch keeps the index form because it repairs the collapse #369 reported without a schema change.

Three confirmations stand (structural tally; the scope comparison failed open on main; the message-slug collapse). The falsifiers were found non-vacuous. The CRUX verdict "below the industry default" is accepted for rule identity and is what #434 closes.
