## CONFIRMED CLAIMS

- **"readOnlyHint is published on the wire and derived from effects."** -> CONFIRMED. `src/mcp/adapter.rs:116` derives the hint dynamically via `v.effects.read_only()`, mathematically guaranteeing a mutating tool cannot falsely advertise `read_only=true`.
- **"The in-tree pmcp adapter drops nothing pforge's did."** -> CONFIRMED. - **"The outputSchema replacement test is pairing-based."** -> CONFIRMED. `tests/falsification_mcp_publishes_readonly_hint_over_stdio.rs:244` specifically asserts `assert_eq!(promised, structured)`, guaranteeing the test evaluates the logical pairing rather than just the absence of the field.

## UNIQUE FINDINGS

- **Schema Drift Root Cause:** The divergence between `forjar mcp --schema` and the real MCP `tools/list` output was entirely an artifact of `pforge_config::ToolInfo::new` hard-setting `annotations: None`. Constructing the `pmcp::Server` natively inside `src/mcp/registry.rs` neatly bypasses this external limitation.
- **Intentional CLI/MCP Resolver Divergence:** The decision to *not* delegate to the CLI's `resolve_state_dir` within the MCP `paths.rs` initially looks like duplicate logic, but is actually a necessary architectural wedge. It prevents recursive double-joining when agents explicitly pass `workspace_state_dir` back into subsequent tool calls, cleanly separating human CLI semantics from stateful agent loops.

## CRUX SURVEY

1. **Terraform (workspaces / `-chdir`)**: Terraform CLI stores the active workspace in `.terraform/environment`. Programmatic interactions and standard CLI invocations (e.g., `terraform plan`) implicitly respect this file unless an explicit `-workspace` is provided. Even when automation uses `-chdir` to shift the project root, the active workspace within that root is preserved. The updated `forjar` design perfectly mirrors this: the MCP server honors the `.forjar/workspace` context relative to the config directory, unifying the agent's view with the human's view.
2. **Pulumi (stacks / Automation API)**: Pulumi stores the active stack in `Pulumi.yaml` or local workspace settings. While the Automation API allows agents to explicitly initialize and select via `Stack::select(stack_name)`, an agent operating over a local project directory correctly inherits the implicitly active stack. `forjar` mimics this boundary by allowing `state_dir` explicit overrides for isolated programmatic interactions, while defaulting to the active workspace to prevent divergent behavior.
3. **MCP Reference Servers**: The official Model Context Protocol reference implementations (like the TypeScript SDK) enforce strict capability compliance. They actively reject tools that advertise capabilities (`outputSchema`) but fail to fulfill the protocol contracts for those capabilities (`structuredContent`). 

**Industry Alignment:** The `forjar` design is **AT** the industry default for workspace context propagation (aligning perfectly with Terraform and Pulumi semantics) and **ABOVE** the industry default for MCP protocol strictness, as many early MCP servers naively publish `outputSchema` schemas without fulfilling the `structuredContent` obligation, causing silent failures on strict clients.
