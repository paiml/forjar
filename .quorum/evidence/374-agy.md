# agy /teamwork lane — #374 (sandboxed plan-mode review, scrubbed HOME)

# VERDICT
The fix attempts to centralize authorization but introduces severe regressions for machine-scoped operators, fails to properly handle canary fleet prompting, and leaves open multiple mutation and execution bypasses via flag combinations. The design falls below industry defaults for access control.

# REFUTED CLAIMS
1. **"check_operator_auth now runs BEFORE every exit, hook and backup"**: Refuted: The combination `apply --check --abort-on-drift` evaluates as a read-only mode to bypass `check_operator_auth`, but still reaches `apply_pre_checks` where `--abort-on-drift` executes `cmd_drift`, performing network probes and mutating the state file with drift status (`src/cli/dispatch_apply_b.rs:192-204`).
2. **"--canary-machine no longer hard-codes yes=true ... confirm before fleet"**: Refuted: The second leg does not ask once for the remaining fleet, but instead loops over `remaining` and calls `cmd_apply` individually, which forces the operator to answer the prompt *N-1 separate times* instead of rolling out after a single fleet confirmation (`src/cli/apply_variants.rs:127-166`).
3. **"the read-only modes stay ungated deliberately" / "gating an invocation that carries hooks is the right line"**: Refuted: The hook exemption misses `--post-script` entirely, and explicitly exempting `--check` creates a deliberate confidentiality leak that allows unauthorized users to read the infrastructure state and diffs of restricted environments (`src/cli/dispatch_apply_b.rs:132-136`).
5. **"any regression: an authorized operator who loses a mode they had"**: Refuted: Because `check_operator_auth` iterates over every machine in the config regardless of the `--machine` filter, an operator authorized only for `sandbox` who runs `apply -m sandbox --refresh-only` is now globally denied for lacking access to `prod`, breaking their previously working scoped workflow (`src/cli/dispatch_apply.rs:125-131`).

# CONFIRMED CLAIMS
4. **"the falsification tests cannot pass vacuously"**: Confirmed: The tests use a fully functional config fixture and explicitly assert the presence of `"not authorized"` in stderr rather than relying on generic non-zero exit codes, proving the logic correctly triggers the authorization gate (`tests/falsification_canary_apply_is_authorized.rs:508-518`).

# UNIQUE FINDINGS
- **Silent Hook Dropping in Canary**: `cmd_apply_canary_machine` calls `cmd_apply` directly and completely bypasses `apply_pre_checks`. As a result, running `--canary-machine` alongside `--pre-script`, `--webhook-before`, or `--abort-on-drift` will silently ignore all of these execution knobs, potentially bypassing required security firewalls or drift validations (`src/cli/dispatch_apply_b.rs:168-179`).
- **Silent Backup Dropping in Read Modes**: Modes like `--diff-only`, `--check`, and `--refresh-only` return from `apply_mode_exits`, which sits above `apply_backups`. Passing `--backup` with these flags will silently do nothing rather than warning the user that no backup was taken.

# CRUX SURVEY
This design falls **below the industry default**.
- **Terraform Cloud/Enterprise**: Uses Sentinel/OPA policies and Workspace permissions. An operator performing a targeted/partial apply (`-target`) must still possess full Workspace `Apply` permissions, and pre-run tasks/Sentinel policies evaluate the *entire context* of the run. You cannot bypass policy checks by combining read-only flags with side-effect flags.
- **Ansible Tower / AWX**: Execution is governed by Job Templates and Inventory-scoped credentials. A user running a Check Mode (dry run) or Limit (canary) execution is validated against the exact subset of inventory they are touching. They are not globally blocked just because the template contains hosts they can't access, provided the limit restricts execution to their authorized subset.
- **Salt (SaltStack)**: The `client_acl` (formerly `publisher_acl`) system scopes execution strictly at the minion level. If a user has `state.apply` permissions for `sandbox` but not `prod`, Salt natively enforces this. A canary run to `sandbox` will succeed, and the subsequent fleet run to `prod` will be denied at the minion level. Forjar's centralized, loop-based global check creates a regression exactly where Salt succeeds. 
- **Pulumi**: Pulumi Cloud stack permissions grant granular update rights. You cannot circumvent stack policies or webhook triggers by passing targeted or read-only CLI flags; the SaaS platform enforces hooks independently of the client execution path.


## Disposition

Four charges, one confirmation, two unique findings.

- Charge 1 (`--check --abort-on-drift` bypasses the gate and probes hosts): ACCEPTED. `abort_on_drift` joins the not-a-read predicate; falsifier added, RED without the change.
- Charge 2 (the fleet leg prompts N−1 times): ACCEPTED. One confirmation for the fleet; falsifier added, RED without the change.
- Charge 3, first half (`--post-script` missing from the predicate): COUNTERED — post_script runs only inside `apply_execute`, unreachable from a read. Second half (`--check` exemption is a leak): DIVERGENCE recorded — the same output is available from ungated verbs; not changed here.
- Charge 5 (scoped operator regression): ACCEPTED. `check_operator_auth` now honours the machine filter; falsifier added, RED without the change.
- Unique finding 1 (`--canary-machine` skips `apply_pre_checks`, so `--pre-script`/`--webhook-before`/`--abort-on-drift` are silently ignored on the canary path): pre-existing, outside #374's gate question — filed as its own ticket.
- Unique finding 2 (`--backup` is a silent no-op in read modes): recorded as a known limit; a read takes no backup because it changes nothing.
- CRUX verdict "below the industry default": accepted for the tree the lane read; the three accepted charges are the gap between that tree and this receipt's.
