### CRUX SURVEY
- **Terraform**: Saved plans (`terraform plan -out=tfplan`) are cryptographically bound to the exact state at plan time. When `terraform apply tfplan` runs, it strictly verifies that the state hasn't drifted. It *does not* prompt for confirmation, as the plan itself acts as the operator's review. Forjar's design contradicts this by running the prompt but skipping the drift guard entirely.
- **Pulumi**: Using `pulumi up --plan` heavily constrains the engine from making un-planned changes, and it evaluates the current live state against the plan at execution time, natively guarding against drift. It also prompts the user for confirmation by default.
- **Ansible**: Lacks a persistent "saved plan" artifact, relying instead on `--check` (dry run) and `--diff`. Because execution is always dynamic, Ansible implicitly accounts for drift during the actual run, never blindly applying a stale delta from a file.
