## VERDICT
The branch implements the three requested verbs (`exec`, `facts`, `doctor --machine`) safely utilizing the existing transport. The architecture is sound, preventing shell injection and avoiding target modifications during diagnostics. However, several claims about the implementation are false: `exec` appends to stderr, `facts` relies on a non-POSIX flag and dangerously coerces parsing errors to zero, and the falsifier test passes vacuously if run as root.

## REFUTED CLAIMS
1. **Claim 1 (exec forwards stderr verbatim):** REFUTED. In `src/cli/exec.rs:114-116`, the `forward` function inspects `out.stderr` and, if it contains "Permission denied", appends an extra hint to stderr (`eprintln!("{hint}");`). Thus, the remote stream does not reach the operator verbatim when this phrase is present.
2. **Claim 2 (facts runs one POSIX sh script; malformed lines are skipped):** REFUTED.
   - The script uses `df -Pi` (`src/cli/facts.rs:42`). The `-i` flag (inodes) is a GNU/BSD extension and is not POSIX compliant.
   - Malformed numeric lines are not skipped. `assign_number` uses `value.parse::<u64>().unwrap_or(0)` (`src/cli/facts.rs:90`), meaning a malformed `uid` or `nproc` silently degrades to `0` instead of being skipped. A malformed `uid` incorrectly reports `root`.
3. **Claim 3 (doctor names directory info when it is not writable):** REFUTED. `dir_check` unconditionally calls `permission_detail` and includes the owner, group, mode, and identity in the `Check` detail, even when the directory *is* writable (`Status::Pass`) (`src/cli/doctor_machine.rs:20-21`). Additionally, `destination_dirs` skips `file` resources that lack a `path` property (`src/cli/doctor_machine.rs:153-155`).
4. **Claim 4 (tests cannot pass vacuously):** REFUTED. The `fj446_doctor_machine_fails_on_unwritable_destination` test contains an early return guard if the test is executed as root (`tests/falsification_446_exec_facts_doctor.rs:112-119`). If the test suite is run in a root CI container, this test returns immediately without asserting anything, thus passing vacuously.

## CONFIRMED CLAIMS
1. **Claim 1 (argv is shell-quoted):** CONFIRMED. `shell_quote` and `shell_join` properly wrap words in POSIX single-quotes (`'...'`) and escape inner single-quotes (`'\''`), making `$` and spaces inert (`src/cli/exec.rs:25-33`).
2. **Claim 5 (reuses transport, no dependencies, no apply path change):** CONFIRMED. `Cargo.toml` is untouched (no new dependencies), all verbs route through `crate::transport::exec_script` (e.g. `src/cli/exec.rs:136`), and the git diff strictly isolates changes to `src/cli/...` without mutating any `apply` codepaths.

## UNIQUE FINDINGS
- **Ignored Resource Types:** `doctor --machine` validates destination directories exclusively for `ResourceType::File` (`src/cli/doctor_machine.rs:150`). It completely ignores destinations for `ResourceType::GithubRelease` or other resources that write to the filesystem, leaving permission bugs for those resources undiagnosed.
- **Incomplete Package Manager Checks:** `package_tool` in `doctor` only checks for `apt`, `apt-get`, `dnf`, and `yum`. If a `Package` resource relies on `pacman`, `apk`, `cargo`, or `uv`, `doctor` silently ignores the tool requirement (`src/cli/doctor_machine.rs:36-42`).

## NOT DELIVERED
The ticket explicitly asks for **"permissions"** as part of its verbatim list of host metadata measurements (along with disk space, inodes, who was trying to write, and PATH).
However, `forjar facts` does *not* measure or report any file or directory permissions. While `doctor --machine` checks permissions for declared `file` destinations, a user asking for general "Host metadata" via `forjar facts` receives no permission information, failing the ticket's requirement to provide it as a standalone measurement.

## CRUX SURVEY
**Security consideration for `exec`:**
The most critical security consideration for an arbitrary remote command runner that wraps operator input in `sh -c` is **Shell/Command Injection**. Unescaped metacharacters (spaces, quotes, `$`, `|`, `;`) in the argv could be evaluated by the target's shell, leading to unintended command execution.
*Is it handled?* Yes. `shell_quote` single-quotes all arguments, neutralizing all shell variables, subshells, and metacharacters before they reach the remote transport.

**Below industry default in a way that matters:**
1. **Missing Network Facts:** Industry defaults (Ansible setup, Puppet facter, Salt grains) gather extensive network metadata (IP addresses, MAC addresses, interfaces). `forjar facts` gathers zero networking data. This matters significantly because IP addresses (e.g., binding to internal vs external IPs) are critical parameters for templating configurations and provisioning.
2. **Silent Failure Coercion:** Industry tools strictly differentiate between "fact not found" and actual values. `facts.rs` silently coerces parsing errors for numbers to `0` (`unwrap_or(0)`). This matters critically because coercing a failed `uid` measurement to `0` falsely reports to the operator that they are connected as `root`, which can dangerously mask permission issues.

## DISPOSITION (orchestrator, after re-running every claim)

- Refuted 1 (stderr not verbatim when a hint is appended) — TAKEN as a wording correction: the remote stderr IS forwarded byte for byte; the hint is one extra line after it, on stderr, only when "Permission denied" appears. The claim now says so.
- Refuted 2a (`df -Pi` is not POSIX) — TAKEN as a wording correction and a known limit: the script is POSIX sh with one df extension (`-i`, present in GNU, BSD and busybox); where it is missing the inode figure is empty and reads as 0.
- Refuted 2b (unparsable numbers coerced to 0; a bad uid reads as root) — TAKEN: `uid` is `Option<u64>` (`None` renders as `uid ?` in every diagnostic), other numbers keep their default instead of being overwritten; `a_uid_that_does_not_parse_is_unknown_not_root` pins it.
- Refuted 3 (owner/mode named even when writable; file resources without `path` skipped) — TAKEN as a wording correction: the detail is always reported and the status is Fail only when unwritable; a `file` resource without a path is not a valid destination.
- Refuted 4 (root guard passes vacuously) — TAKEN: under root the case now asserts the naming half (directory, mode, identity) and skips only the exit-code half; pmat's silent-skip flag is gone.
- Unique 1 (only `file` destinations) — CARRIED as a known limit (other writing resource types are queued with E11).
- Unique 2 (package managers) — TAKEN: the provider→executable table now covers apt/dnf/yum/zypper/pacman/apk/brew/snap/cargo/uv/pip.
- Not delivered (permissions as standalone facts; network facts) — network facts TAKEN (`ipv4=` lines, rendered and in `--json`); standalone permission facts NOT taken — permissions are meaningful against a destination, which `doctor --machine` reports per declared resource; a bare "permissions" fact has no subject. Recorded as a known limit with that reason.
- CRUX (shell injection) — CONFIRMED handled by `shell_quote`; agreed.
