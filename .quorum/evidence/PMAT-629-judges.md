# Judges — the nightly rebuilds whenever its tag is not HEAD (PMAT-629)

Round count and heads: see `PMAT-629-lanes.md`.

## CONFIRMED

1. [gate] C1 — The gate writes has_commits=true when the nightly tag is behind HEAD on a quiet day or absent, and false when it is at HEAD, with a manual dispatch still forcing a build; all nine forjar lane verdicts agreed.
   - evidence: the three histories run at `tests/falsification_nightly_gate_is_tag_vs_head.rs:154`, `tests/falsification_nightly_gate_is_tag_vs_head.rs:164` and `tests/falsification_nightly_gate_is_tag_vs_head.rs:180`, every commit dated thirty days back at `tests/falsification_nightly_gate_is_tag_vs_head.rs:93`, and the tag is annotated at `tests/falsification_nightly_gate_is_tag_vs_head.rs:113` so the gate must peel it.
2. [release] C2 — After round 2 the release step passes target_commitish set to the run's github.sha, so the recreated tag names the commit this run built even when another commit lands on main while it builds.
   - evidence: asserted as a parsed field of the one softprops step at `tests/falsification_nightly_gate_is_tag_vs_head.rs:211`; round-3 lanes in both families read the step and agreed.
3. [test] C3 — The falsifier lifts the parsed run script of the step whose id is check, substitutes only the event-name expression, and runs it under bash with errexit and pipefail, reading the verdict from the GITHUB_OUTPUT file.
   - evidence: `tests/falsification_nightly_gate_is_tag_vs_head.rs:65` selects the step by id and `tests/falsification_nightly_gate_is_tag_vs_head.rs:75` substitutes, `tests/falsification_nightly_gate_is_tag_vs_head.rs:122` runs it, and `tests/falsification_nightly_gate_is_tag_vs_head.rs:146` requires exactly one has_commits line, so a script that writes nothing fails.
4. [test] C4 — Each declared mutation was applied to the workflow and measured: restoring the 24h gate failed two tests, an unconditional gate failed one, and deleting target_commitish failed one, and the byte-identical restore went green.
   - evidence: the mutations are declared in the header of `tests/falsification_nightly_gate_is_tag_vs_head.rs:40`, and the restore was checked with git status showing only the new test untracked before the rerun passed four of four.
5. [checkout] C5 — The check-activity checkout keeps fetch-depth zero, so the nightly tag is present in the clone the gate reads, and without it the tag would be absent and every scheduled run would rebuild.
   - evidence: asserted as a parsed field at `tests/falsification_nightly_gate_is_tag_vs_head.rs:227`, which fails if the depth is removed or changed.

   - corrected: found by copia's round-1 lane 3 on the identical step, pinned to github.sha on both repositories, and now asserted at `tests/falsification_nightly_gate_is_tag_vs_head.rs:211`.

   - corrected: line 2 now says the file is maintained in this repository and names the deletion, and line 6 describes the tag-versus-HEAD skip.

   - evidence: the step before publishing runs gh release delete nightly with cleanup-tag, so publishing always creates the tag fresh, and where it lands is pinned at `tests/falsification_nightly_gate_is_tag_vs_head.rs:211`.
